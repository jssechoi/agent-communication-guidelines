# 문서형 산출물 교정 사례 (Korean Document Revision Case)

AI가 작성한 사내 공모전 지원서 문안을 사람이 직접 교정한 기록입니다. 교정 사유는 "너무 AI 같고 번역체"였습니다.
아래 대조 쌍은 두 문서에서 그대로 옮긴 것입니다. GUIDELINES.md 2.1·2.2·6장의 근거 자료입니다.

- 수정 전: `jssechoi/materials` — `tools/email-softener/docs/마케팅_AI_활용_공모전_지원서_문안.md`
- 수정 후: `jssechoi/materials` — `tools/email-softener/docs/지원서_수정본.txt`

---

## 1. 소제목을 명사구로 (6.1)

교정한 소제목 다섯 개 전부가 같은 방향으로 바뀌었습니다. 줄표 촌평과 서술형 종결이 사라지고, 항목의 내용을 지칭하는 명사구가 됐습니다.

| 수정 전 | 수정 후 |
| :--- | :--- |
| `[프롬프트 — 사람이 아니라 앱이 만듭니다]` | `[앱이 생성하는 프롬프트]` |
| `[단계별 대화 과정 — 한 번 부르고 끝냅니다]` | `[한번의 생성 요청으로 원문 분석, 메시지 작성, 검토, 이력 관리 수행]` |
| `[AI 설정]` | `[AI 사용 수준 조절 기능]` |
| `[AI 산출물 검증 기준]` | `[소스 코드와 AI서비스의 산출물 혼합 검증 방식]` |
| `[이 방식을 검증한 근거]` | `[앱의 메시지 생성 방식에 대한 자체 테스트 수행]` |

명칭 항목도 설명문에서 명사구로 바뀌었습니다.

- 수정 전: `메일 한 통에 도구 넷을 오가던 작업을 창 하나로 통합`
- 수정 후: `메일/메시지 작성 에이전트 '문율'`

## 2. 어휘 수준 (2.1)

압축된 토박이말 동사와 비유가 업무 표준 어휘로 올라갔습니다. 이 문서에서 어휘를 낮춘 표현은 하나도 살아남지 않았습니다.

| 수정 전 | 수정 후 |
| :--- | :--- |
| `판정만 이력에 더합니다` | `판정만 이력에 추가합니다` |
| `수치는 ~ 다시 세지 말라고 명시합니다` | `수치는 ~ 다시 평가하지 말라고 명시합니다` |
| `값이 그대로 보존되고` | `데이터가 그대로 보존되고` |
| `한 통에 도구 넷을 오갑니다` | `메시지 작성에 시간이 소요됩니다` |
| `그래서 어려운 메일일수록 뒤로 밀리고` | `그래서 신경써야 할 메일일수록 작성이 오래 걸리고` |
| `그 지연이 정산과 결정을 늦춥니다` | `그 지연으로 의사 결정과 업무 진행이 밀립니다` |
| `사용자가 고르는 것은 넷뿐입니다` | `사용자가 고르는 것은 네가지 뿐입니다` |

## 3. 번역투 구문 (2.2)

한 문장에서 사역과 관계절이 동시에 걷혔습니다.

- 수정 전: `항목마다 예·아니오·해당 없음 하나를 고르고, 판단의 출처가 되는 문장을 원문에서 그대로 인용하게 합니다.`
- 수정 후: `항목마다 예·아니오·해당 없음 하나를 고르고, 판단의 출처 문장을 원문에서 그대로 인용합니다.`

지시어로 문장을 잇던 자리는 접속부사가 대신했습니다.

- 수정 전: `여기에 영문 번역, 금액·날짜 대조, ~ 검색이 붙어`
- 수정 후: `추가로 영문 번역, 금액·날짜 대조, ~ 검색이 붙어`

## 4. 부정 서술을 긍정 서술로 (6.2)

| 수정 전 | 수정 후 |
| :--- | :--- |
| `검산을 AI에게 맡기지 않습니다. 코드가 다섯 가지를 대조합니다.` | `산출물은 기본적으로 코드로 다섯 가지 항목을 대조하여 검토합니다.` |
| `AI 검토는 일곱 항목이며 점수를 매기지 않습니다.` | `AI 는 일곱 항목을 기준으로 검토합니다.` |

## 5. 나열을 목록으로 (6.3)

문장 안에 이어 붙인 다섯 개 사례가 줄로 갈라졌습니다.

- 수정 전: `~ 상황에 맞습니다 — 협력사에 대금·일정을 독촉할 때, 고객 요청을 거절할 때, 임원에게 지연을 보고할 때, 타 부서에 이의를 제기할 때, 채용 후보자에게 결과를 알릴 때입니다.`
- 수정 후:

```
데이터가 그대로 보존되고 말투가 결과를 좌우하는 상황에 맞습니다:
 - 협력사에 대금·일정을 독촉할 때
 - 고객 요청을 거절할 때
 - 임원에게 지연을 보고할 때
 - 타 부서에 이의를 제기할 때
 - 채용 후보자에게 결과를 알릴 때.
```

주의사항 항목도 한 문단에서 네 줄 목록으로 바뀌었습니다.

## 6. 단정의 범위 (6.4)

확인하지 않은 인과 하나만 개연으로 완화됐습니다. 같은 문단의 다른 단정문(`이런 메일은 쓸 내용이 아니라 어조에서 막힙니다`)은 그대로 남았습니다.

- 수정 전: `담당자가 바뀌면 같은 상황에서도 결과가 달라집니다.`
- 수정 후: `담당자가 바뀌면 같은 상황에서도 다른 결과로 이어질 수 있습니다.`

## 7. 삭제된 내용 (6.5·6.6)

### 계측하지 않은 값 — 전량 삭제

`[정량 — 실제 호출에서 측정한 값]`, `[체감 — 아직 계측하지 않은 값]`, `[아직 측정하지 않은 항목]` 세 블록이 통째로 빠졌습니다. `10분 남짓 → 3분 안팎`에는 "지원자 체감이며 계측한 값이 아닙니다"라는 단서가 달려 있었으나 단서째 삭제됐습니다. 한계 항목의 `언어 교차는 표본이 일곱 건입니다. 첫 작성 속도는 일부 구간만 개선했고 나머지는 측정하지 않았습니다.`도 같이 빠졌습니다.

### 과정 서술 — 삭제

- `경량이 빠를 것으로 예상했으나 실제 측정에서 더 느려, 기본값을 표준으로 되돌렸습니다.`
- `3회차는 사용량 한도 경고에서 자동으로 중단됐습니다.`
- `Claude 또는 Gemini를 호출합니다. 제출한 예시는 전부 Claude 호출입니다. 어느 쪽이든` (도구 선택에 대한 자기 해명)

### 남은 한계 — 유지

사용자가 운용 중 부딪히는 제약 네 가지는 그대로 남았습니다. 삭제 기준이 "불리한 내용"이 아니라 "읽는 사람이 쓰지 않는 내용"이었음을 보여 줍니다.

```
- 보내기 전 확인은 사람이 해야합니다. ~
- 자동 발송 기능이 없어 복사까지만 지원합니다.
- 민감정보 탐지는 규칙 기반이라 새로운 표기를 놓칠 수 있어, ~
- 초안과 결과는 PC 안 SQLite에 평문으로 남으며, ~
```

여기서 `사람이 합니다`가 `사람이 해야합니다`로 **강화**됐습니다. 2장의 강제 어미 금지는 독자에게 행동을 재촉하는 용법에만 걸리며, 생략 불가한 점검 지점을 서술할 때는 적용하지 않습니다.

## 9. 문항 대응 (6.8)

문항이 `사람은 어떤 일을 맡았는지 설명`을 요구했으나 원안에는 사람의 역할이 없었습니다.

- 수정 전: `회차별 기록을 남겼습니다.`
- 수정 후: `회차별 기록을 남겨 직접 검토했습니다.`

## 문체 외 수정 (규칙 대상 아님)

기록의 완결성을 위해 남깁니다. 아래는 문체가 아니라 사실·범위 교정입니다.

- `기한이 지난 대금을` → `기한이 지난 약속을` (독촉 대상 일반화)
- 자동 시험 `635` → `632`, 합계 `753` → `750` (수치 정정)
- B-3의 `담당자가 바뀌어도` → `사용자가 바뀌어도` (용어 통일. 같은 문서 B-2의 `담당자`는 유지)
- `Windows에서 실행한 작성 화면과 이력 화면도 함께 실었습니다.` 삭제 (제출물 범위)
- `사용 방법은 같은 문서 뒤쪽에 있습니다` → `사용 방법도 같은 문서에 넣었습니다` (위치 안내 → 행위 서술)

# 보고 형식 (Report Format)

`SKILL.md` §5 에서 보고 형식으로 정한 문서에 적용합니다. 평가·분석 보고서, 현황 보고, 보고·발표 장표가
기본 대상입니다. `document-rules.md` 를 함께 적용하고, 합쇼체 종결과 문의 회신 골격(M1)은 적용하지
않습니다. `humanize-ko` 의 종결 변주, 문장 단축, 목록 축소도 적용하지 않습니다.

컨설팅사 평가 보고서 2건(문서형·장표형)의 공통 관행을 옮긴 규칙입니다. 두 보고서가 사람이 쓴 글로 읽히는
이유는 평가어마다 붙는 구체 근거와, 대상마다 반복되는 틀입니다.

## R1. 결론을 맨 앞에 둡니다

- **문서형**: 첫 블록에 총평을 두고, 판단 1~2문장과 그 전제를 씁니다(`[대상]은 [기준] 측면에서 [판단]으로
  판단됨. [단계·조건]을 감안한 평가임`).
- **장표형**: 장표마다 제목 아래 한 줄 메시지로 그 장의 결론을 씁니다. 메시지는 판단이나 필요한 조치로
  끝냅니다(`[대상] [개선 사항] 필요`). `측정 결과`처럼 주제명만 쓴 메시지는 결론이 아닙니다.
- **마무리**: 마지막 블록에는 종합 판단과 기대 효과를 씁니다. 앞 내용을 다시 요약하는 결론 절은 두지 않습니다.

## R2. 같은 종류의 대상은 같은 틀로 반복합니다

- **문서형 틀**: 개요(1문장) → 강점 → 개선기회 → 제언 → 비교 수준 → 종합.
- **장표형 틀**: 평가 대상과 항목 정의 → 측정 기준과 척도 → 대상별 결과 → 대상별 조치(부록). 결과 장표와
  조치 장표는 대상마다 한 장씩 짝을 맞춥니다.
- **문제와 조치의 짝**: 개선기회와 제언은 같은 순서로 1:1 대응시킵니다. 짝이 없는 제언은 끝에 둡니다.
- **공통 사항**: 여러 대상에 공통인 권고는 대상별 블록에서 반복하지 않고 `공통 권고` 블록으로 모읍니다.

## R3. 종결은 블록의 기능에 맞춥니다

본문 전체를 개조식 명사형으로 끝내고, 한 블록 안에서는 형태를 바꾸지 않습니다. 합쇼체와 해라체를 섞지
않습니다. 판단 강도는 `SKILL.md` §4 를 따릅니다.

| 블록 | 종결 | 예 |
| :--- | :--- | :--- |
| 현황·강점 | 완료 동작 `~함` 또는 동작 명사 | `설계함`, `확보함`, `반영` |
| 문제·개선기회 | 상태 표현 | `부족함`, `부재함`, `미흡`, `불일치 발생`, `위험이 있음` |
| 조치·제언 | 당위 `~해야 함`·`~필요` 또는 조치 명사 | `표준화해야 함`, `개선 필요`, `검증 로직 추가` |
| 판단 | 피동 판단 | `~로 판단됨`, `~로 예상됨` |
| 미확인 | 미확인 표시 | `~여부가 명확하지 않음`, `~확인 필요` |

개조식에서는 `이/가`, `을/를` 같은 조사를 줄일 수 있습니다(`중복 문항 생성되지 않도록 필터링 로직 강화`).
조사를 빼서 주체나 대상이 바뀌어 읽히면 남깁니다.

## R4. 항목은 `라벨: 설명`으로 씁니다

라벨은 명사구이고 설명은 1~2문장입니다. 라벨만 읽어도 판단이 드러나도록 블록마다 형태를 달리합니다.

| 블록 | 라벨 형태 | 예 |
| :--- | :--- | :--- |
| 강점 | 평가어 + 명사 | `정확한 발언자 구분` |
| 개선기회 | 문제 명사(부재·부족·불일치·모호성·한계) | `결정 사항 누락`, `용어 표기 불일치` |
| 제언·조치 | 조치 명사(도입·구축·강화·표준화·정비·단일화) | `용어 사전 적용` |
| 비교 수준 | `항목: 등급. 근거` | `외부 시스템 연계: 중. [비교 대상]은 [기능]을 운영 중임` |

장표형의 조치 장표는 조치 라벨을 제목 상자로 두고, 그 아래 항목 2~3개로 구체 조치를 씁니다.

## R5. 평가어에는 구체 근거를 붙입니다

`적절한`, `직관적인`, `견고함`, `우수함` 같은 평가어는 같은 항목 안에 근거가 있을 때만 씁니다. 근거가
없으면 평가어를 지우고 관찰한 사실만 씁니다. 사람이 쓴 보고서와 AI 초안의 차이가 가장 크게 드러나는 곳입니다.

- **측정값**: 평균과 함께 회차별 값이나 범위를 괄호로 붙입니다(`평균 [n]분 소요([1차] / [2차] / [3차])`).
- **고유명사**: 시스템명, 데이터 원천명, 기능명, 화면의 버튼 문구.
- **재현 사례**: 문제 항목 아래 `예:` 한 줄로 입력 조건과 관찰 결과를 씁니다.
- **비교 대상의 동작**: `[비교 대상]은 [기능]을 [방식]으로 운영함`.

`humanize-ko` 가 지우는 공허한 수식어(`효율적인`, `핵심`, `종합적으로`)도 이 기준으로 판정합니다. 근거가
붙으면 유지하고, 근거 없이 꾸미기만 하면 삭제합니다.

## R6. 판단에는 기준과 조건을 붙입니다

- **단계 조건**: 초기 버전이나 시범 운영처럼 평가 시점의 조건을 판단에 붙입니다. 조건에 따라 판단이
  달라지면 두 문장으로 나눕니다(`1차 릴리즈 기준으로는 견고함. 운영 기준까지는 [과제] 보강 필요`).
- **비교 기준**: 비교 대상(선도 사례, 기준값, 이전 버전)을 밝히고, 외부 기준값에는 출처를 표시합니다.
- **척도**: 등급(`상·중상·중·중하`)이나 점수(1~5점)를 쓰면 척도 정의를 결과보다 앞에 둡니다. 외부 기준을
  바꿔 적용한 항목은 표에서 강조하고 범례를 붙입니다.
- **평가 불가**: 측정하지 못한 칸은 `N/A`와 사유 한 줄로 둡니다. 점수를 추정해 채우지 않습니다.
  미확인 처리는 D8 을 따릅니다.

## R7. 범위와 제외를 밝힙니다

- **제외 항목**: 평가에서 뺀 항목은 지우지 않고 흐린 서식으로 두고, 옆에 제외 사유를 씁니다.
- **우선순위 단서**: 이번 범위의 우선순위가 아닌 사항은 해당 블록 바로 위에 `[참고: ...]`로 밝힙니다. 예외
  항목이 있으면 단서 안에 적습니다.
- **부록**: 상세 조치와 근거 자료는 본문 뒤 부록으로 보내고 제목 앞에 `[Back Up]`을 붙입니다.

## R8. 용어와 기호

- **원어 용어**: 업계 용어·약어·화면 문구는 원어로 씁니다(`RBAC`, `Hold-out`, `Quick Fix`). 일반 동사·명사는
  영어로 바꾸지 않습니다(`mitigate함` → `완화함`).
- **병렬**: 짧은 명사 둘~셋은 `/`나 `·`로 묶습니다(`품질/최신성`, `정확·일관`). 문장이나 긴 구에는 쓰지 않습니다.
- **흐름과 결과**: 순서는 `A → B → C`, 관찰에서 판단으로 이어지면 `→`(`평균 [n]초 소요 → 기준 대비 빠름`).
- **개념명과 화면 문구**: 작은따옴표(`'저장'·'다음' 버튼`).
- **세미콜론**: 한 항목 안에서 판단과 비교 근거를 이을 때(`권한 상속 여부가 명확하지 않음; [비교 대상]은 최소
  권한으로 상속함`).
- **한자 약어**: `有`·`無`·`時`·`後`·`必`·`例`는 사내 장표 관행이 있을 때만 쓰고, 외부 독자 문서에는 쓰지 않습니다.

## R9. 장표 구성

- **제목**: `[절 번호]. [절 이름] > [대상명]` 경로형. 한 내용이 여러 장이면 `(1/2)`.
- **메시지 줄**: 제목 아래 한 줄로 그 장의 결론(R1). 두 줄을 넘기지 않습니다.
- **대상 탭**: 평가 대상이 여럿이면 모든 결과 장표의 같은 위치에 대상 목록을 두고 현재 대상만 강조합니다.
- **결과 장표**: 한 장에 시각화, 근거 표, 결론 상자를 함께 둡니다(예: 왼쪽 기준값 대비 비교 차트, 오른쪽
  `항목 | 점수 | 근거` 표, 아래쪽 `Result` 상자). 결론 상자는 모든 결과 장표에서 같은 위치에 둡니다.
- **강조**: 조치나 판단에 해당하는 구절만 강조색으로 표시합니다. 근거와 예시는 작은 글씨로 해당 항목 바로 아래 둡니다.
- **정의 장표**: 외부 기준과 자사 적용을 나란히 비교하고, 다르게 적용한 칸만 배경색과 범례로 표시합니다.
- **쪽 번호**: 모든 장에 `n / 전체`.

색 단독 구분 금지와 렌더링 확인은 D11, 문장 경계 줄바꿈은 D12 를 따릅니다.

## R10. 재현하지 않는 요소

이 형식은 사람이 쓴 보고서의 구성과 구체성을 따르고, 실수는 따르지 않습니다.

- 오탈자, 띄어쓰기 오류(`맞는 지`), 조사 누락으로 문장이 성립하지 않는 경우
- 마침표 유무, 따옴표 방향, 같은 주체의 호칭(`당사`·`자사`) 혼용
- 제목과 대상 탭의 불일치, 문장이 끝나지 않은 결론 상자
- `매우` 같은 강조 부사
